# ESG 期末考互動複習網站 — 實作規格

> 使用者：參加 ESG 課程的學生，期末考即將到來。
> 考試範圍：GRI 全部內容為主（**新準則版**），IFRS S1／S2 與 TCFD 為輔，教材與考卷都是中文。
> 目標：考前一天半內，用「點擊、翻卡、出題、找碴」快速、有秩序地記住細節。
> 時間很緊：**先做出能用的 v1，當天就部署**，細節之後再補。

## 2. 內容來源（不可自行編造）

所有知識內容都在 `content/`，**網站只能顯示這些檔案裡的內容**，不可另外寫入未經來源支持的事實、數字或題目。

| 檔案 | 內容 |
|---|---|
| `content/standards.json` | GRI 1、2、3、101–103、200、300、400（另含行業準則資料，但 GRI 條文頁與翻卡不列入）；200／300／400 系列的揭露細項在 `details`（中文＋英文原文） |
| `content/frameworks.json` | 三欄對照、TCFD 11 項建議、IFRS S1／S2 重點與 2025 修正、台灣接軌 |
| `content/quiz.json` | 48 題選擇題，每題附解析與來源 |
| `content/flashcards.json` | 20 張概念卡；另須由程式從 `standards.json` 自動產生編號卡 |
| `content/spot-the-error.json` | 8 段找碴題 |
| `content/sources.json` | 所有來源的標題、發布者與網址 |

規則：
- 來源只在網站最下面放一份總清單（取自 `sources.json`，連結另開分頁），不在每題、每張卡旁重複。
- 若之後使用者上傳教材，教材用語優先，只改 `content/`，不改程式。

## 3. 設計規範

### 3.1 指定條件（使用者要求，不可更改）

- **底色：白色**
- **主色：橘色**
- **輔色：淡橘色**
- **字體：思源黑體（Noto Sans TC）**，依資訊層級調整字重
- **資訊分成不同 bar**，搭配**互動式點擊元件**

### 3.2 色彩 token（全部宣告在 `:root`，之後只用 token）

| Token | 值 | 用途 |
|---|---|---|
| `--c-bg` | `#FFFFFF` | 頁面底色 |
| `--c-ink` | `#1F1A17` | 內文 |
| `--c-ink-soft` | `#5C534D` | 次要文字（對白底對比 ≥ 4.5:1） |
| `--c-primary` | `#C2410C` | 主色：按鈕底、選中狀態、重點數字（白字對比 ≥ 4.5:1） |
| `--c-primary-strong` | `#9A3412` | 按下（active）、hover 加深 |
| `--c-accent` | `#FFEDD5` | 輔色：bar 底、卡片底、選中列底色 |
| `--c-accent-line` | `#FDBA74` | 輔色線條：bar 分隔、外框 |
| `--c-correct` | `#15803D` | 答對（一定要搭配文字或圖示，不可只靠顏色） |
| `--c-wrong` | `#B91C1C` | 答錯（同上） |
| `--c-focus` | `#C2410C` | focus 外框 |

橘色只用在需要注意的地方（主要動作、選中、重點編號），不要整片塗橘；大面積用白與淡橘。

### 3.3 字體與字重層級

以 Google Fonts 載入 `Noto Sans TC`，字重 400／500／700／900，`font-display: swap`。字體同樣宣告為 token（`--f-sans`）。

| 層級 | 字重 | 尺寸 | 用於 |
|---|---|---|---|
| 編號展示 | 900 | 40–56px | 樓層大編號（GRI 2、101）、倒數數字 |
| 標題 | 700 | 24–32px | 模組標題、樓層名稱 |
| 小標 | 700 | 18–20px | bar 標題、題目 |
| 標籤 | 500 | 14px | 分類、狀態、按鈕文字 |
| 內文 | 400 | 16–17px，行高 1.7 | 說明、解析 |

### 3.4 「bar」的版面語言

整站由水平的 bar 堆疊而成：

1. **頂部模組 bar**（sticky）：GRI 條文／對照／翻卡／測驗／找碴／錯題本。目前模組底色用 `--c-primary`、白字；其他是白底。手機版改成橫向捲動。
2. **主題篩選 bar**：GRI 1、GRI 2、GRI 3、101–103、200、300、400、行業、TCFD、IFRS、台灣。可複選的膠囊按鈕，翻卡、測驗、找碴共用。
3. **內容 bar**：每個資訊單元是一條全寬 bar（淡橘底或白底配淡橘線），點擊後原地展開（accordion），不跳頁。
4. **進度 bar**：測驗與翻卡頂端顯示進度條（題數、正確率）。

### 3.5 Hallmark 規範（必遵守）

實作時執行 `/hallmark`，並遵守其 Floor 規則，特別是：
- 所有顏色、字體都經過 `:root` token
- 不使用 `transition: all`，不對 width／height／top／left 做動畫；只動 `transform` 與 `opacity`
- 每個互動元件都要有立即出現的 `:focus-visible`
- 所有動畫都有 `prefers-reduced-motion: reduce` 的替代
- 標籤不用全大寫、不加字距，不用 emoji 當圖示，不做卡片裡再套卡片
- `html, body { overflow-x: clip; }`
- 版面寬度有上限並置中
- 不放任何編造的數字、見證或 logo
- 交付前執行 sloplint，修掉所有 FAIL

## 4. 功能規格

### 4.1 GRI 條文

- 單一清單，依編號**由上往下**：GRI 1 → GRI 2 → GRI 3 → GRI 101–103 → 201–207 → 301–308 → 401–418（最下面是 418）。
- 頂部有跳轉列可直接跳到各組；每組顯示大編號（字重 900）＋中文名稱＋一句話。
- 每一號準則是一條可展開的 bar，展開後列出全部揭露細項（如 201-1 至 201-4），內容來自 `standards.json`：
  - `keyPoints`：每組是一條可展開的 bar
  - `sections` / `disclosures` / `standards`：編號＋名稱的清單，每列可點，點了顯示說明（第三欄）
  - `replaces` / `effective` / `status`：新準則顯示「取代誰、何時生效、目前狀態」三個標籤
- **遮罩記憶模式**（切換鈕）：隱藏所有中文名稱，只露編號，點一下才翻開，用來自我測試。

### 4.2 對照

- 三欄對照表（`comparison.rows`）：每列是一條 bar，可點擊只看某一欄（例如只亮 GRI 欄），其他兩欄淡化。
- 「雙重重大性」說明 bar。
- TCFD 四支柱：四條 bar，點開看建議揭露；旁邊顯示「2・3・3・3＝11」。
- 轉型風險與實體風險：兩組可點的標籤，點了顯示說明。
- IFRS S1、S2、2025 修正：各一條可展開的 bar。
- 台灣接軌時程：橫向三段時間軸 bar（2026／2027／2028），點了顯示適用對象。

### 4.3 翻卡

- 牌組來源：
  1. `flashcards.json` 的 `conceptCards`
  2. 由 `standards.json` 自動產生：每一條揭露與每一號準則各產生正向（編號 → 名稱）與反向（名稱 → 編號）兩張
- 點卡片翻面（3D 翻轉，只用 transform；reduced-motion 改為淡入淡出）。
- 翻面後有三個按鈕：**不會**／**有點模糊**／**會了**，鍵盤快捷鍵 1／2／3，空白鍵翻面。
- 間隔重複：Leitner 五個盒子。「不會」回盒 1；「有點模糊」維持原盒；「會了」升一盒。盒 1 出現機率最高。
- 篩選：主題 bar、方向（正向／反向／混合）、只看新準則。

### 4.4 測驗

- **練習模式**：依主題篩選，逐題作答，作答後立即顯示對錯與解析。
- **模擬考模式**：從全部題庫隨機抽 20 題，限時 15 分鐘，作答期間不顯示答案，交卷後一次看成績與每題解析。
- **錯題重練**：只出答錯過的題。
- 選項順序每次打亂（正確答案以 id 判斷，不受順序影響）。
- 鍵盤：1–4 選答案、Enter 下一題。
- 成績頁：總分、各主題正確率（橫向 bar 圖），並列出最弱的 3 個主題，附「去翻這個主題的卡」按鈕。

### 4.5 找碴

- 每題顯示一段報告書片段，句子逐句列成可點的 bar。
- 使用者點選認為有錯的句子（可複選），按「送出」。
- 揭曉：正確抓到的錯句、漏抓的錯句、誤判的正確句分別標示（顏色＋文字標籤），並在錯句下方展開修正說明。

### 4.6 錯題本

- 彙整測驗答錯的題目、找碴漏抓的句子、翻卡在盒 1 的卡片。
- 依主題分組，每組一條 bar 顯示數量，點開列出內容，並可一鍵進入該主題的重練。
- 「清除紀錄」需二次確認。

### 4.7 首頁／倒數

- 一句標題、一句說明、一個主要按鈕（「開始模擬考」）、一個次要按鈕（「從 GRI 條文開始」）。
- 距考試日的倒數（考試日由使用者在頁面上自行設定，只存在自己的瀏覽器；以台北時間計算，只顯示天與小時）。
- 各模組完成度 bar。

## 5. 技術規格

- **純靜態網站**：Vite＋原生 TypeScript（或原生 JS），不使用後端、不需要資料庫。
- 內容以 `import` 或 `fetch` 讀取 `content/*.json`。
- 學習紀錄存在 `localStorage`，所有讀寫包在 `try/catch`，讀不到時當作新使用者，不可讓頁面壞掉。
- 單頁應用，用 hash 路由（`#/building`、`#/quiz`…），重新整理不會 404。
- 手機優先：主要使用情境是手機通勤複習，360px 寬也要能用，點擊區至少 44×44px。
- 無障礙：語意化 HTML、`aria-expanded` 用在所有展開 bar、對錯不只靠顏色。
- 加上 `<meta name="robots" content="noindex, nofollow">`，並提供 `robots.txt` 禁止索引。
- 建立 `scripts/validate-content.mjs`，build 前驗證：每題 `answer` 存在於 `options`、找碴 `errors` 索引有效、所有 `source` 都在 `sources.json`。驗證失敗時 build 失敗。

## 6. 部署：Vercel，並限制存取

使用者要求「只有擁有網站連結的人才能檢視」，且已選擇用 Vercel 真正限制存取。

1. 用 Vercel CLI 或 Vercel MCP 建立專案並部署（`vercel deploy --prod`）。
2. 開啟 **Deployment Protection**：
   - 先用 `get_project_deployment_protection` 查目前設定與方案可用的選項。
   - 啟用 Vercel Authentication，涵蓋範圍盡量包含 production（`ssoProtection.deploymentType`，方案允許時用 `all`）。
   - 用 **Shareable Link**（Vercel MCP `get_access_to_vercel_url`，或 dashboard 的 Share 按鈕）產生可繞過保護的連結，交給使用者。
3. **注意方案限制**：Hobby 方案的 Standard Protection 可能不保護 production 網域本身。部署後務必用無痕視窗實測：
   - 直接開 production 網址 → 應被擋下
   - 開 Shareable Link → 應能看到網站
   - 若 production 網域無法保護，改為只分享受保護的部署網址＋Shareable Link，並清楚告訴使用者哪個網址可分享、哪個不可以。
4. **Password Protection 可能產生費用**，不可自行開啟；需要時請使用者自己在 dashboard 決定。
5. 部署完成後回報：可分享的連結、保護方式、實測結果。
